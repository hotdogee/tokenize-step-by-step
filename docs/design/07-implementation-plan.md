# 07 — Implementation plan (area G)

*Work packages for parallel Opus 5.5 agents. Each package owns the paths listed in `02-architecture.md` §8, ships with its own tests, and is reviewed by a second agent against its acceptance criteria. PRs ≤ 600 lines where possible. Sizes: S ≤ 1 agent-day, M 2–3, L 4–6.*

## 1. Interface freeze

WP00 commits the FROZEN v1 contracts verbatim from the design: `packages/core/src/model/result.ts` (03 §B.1–B.2, incl. `NEVER`/`ALIVE`), `packages/core/src/model/view-types.ts` (03 §B.2: `CharInfo`, `TokenInfo`, `PartsAt`, `StepSentence`, `Fragment`, `RowModel`), `packages/core/src/format/types.ts` (03 §B.8, C.2), `packages/core/src/protocol.ts` (04 §6: messages, `Features`, `Progress`, `LoadedInfo`, `LookupEntry`, `AssetSummary`, `TokenizerClientLike`), `packages/core/src/fixture/fixture-types.ts`, `packages/registry/src/schema.ts` (03 §B.7, incl. `TextLangChoice`/`ResolvedTextLang` and the nullable `ModelRow.tokenizer`), the `PairPriority`/`MergeState`/`Tokenizer` contracts (04 §1.1, 03 §B.6) and the TSBV1 layout (`packages/core/src/format/README.md`, 03 §C.1), each with a `// FROZEN v1 — see docs/design/…` header. A change needs an ADR in `docs/adr/` and one PR that updates every dependent in the table below. Mocks that unblock parallel work: `MockTokenizerClient` (fixture results; WP01 via `fromFixtureCase`), dev loaders `loadTiktokenText` / `loadSpmModel` / `loadHfJson` (WP03, available from day one of wave 1 as plain readers) so engine agents never wait for the converter.

**Interim conformance gate (AD-32).** `pnpm build` runs `vocab:build`, which runs `@tsbs/conformance` with the real engines (AD-13) — but the engines are wave 2. Until **both** WP05A and WP05B have merged, CI runs `vocab:build --conformance skip-missing-engine` (repository variable `CONFORMANCE_MODE`): conformance is skipped only for a family whose engine factory `@tsbs/core` does not yet export, with a visible warning per skipped asset, and the `vocab`/`unit`/`build` jobs are green from WP00 onwards. The PR that lands the **second** engine flips `CONFORMANCE_MODE` to `strict` in the same PR (its author owns the flip; WP11 verifies the gate is hard and adds a check that `strict` is set whenever both factories exist). `--conformance off` is local-only and never in CI.
