# ADR 0002 — `TSBV1`: one self-describing, pre-gzipped binary container per vocabulary

- **Status:** Accepted (2026-10-25). Stub written by WP00; WP02 (reader) and WP03 (writer) may extend the rationale.
- **Layout (FROZEN v1):** `packages/core/src/format/README.md` (verbatim copy of `docs/design/03-data-model-and-assets.md`
  §C.1); in-memory types in `packages/core/src/format/types.ts`.

## Context

Upstream vocabularies come in six formats (tiktoken rank files, SentencePiece protos, HF `tokenizer.json`, Grok-2 JSON,
the legacy Claude JSON) and two of them exceed the 25 MiB per-file limit of Cloudflare static assets. Edge compression
drops `Content-Length` (no exact progress) and saves only 2–3 % over gzip-9; `DecompressionStream('brotli')` is missing in
Chrome. The Worker needs byte-keyed lookups with small resident memory on 3 GB phones.

## Decision

- One little-endian section container per tokenizer: `META PCES TYPS PRIO|SCRF MRGS SPCL`, every section length-prefixed
  so readers can skip unknown tags; unknown `version` is rejected (03 §C.1, AD-10).
- Pre-gzipped at build (zopfli or zlib-9, deterministic), served as opaque `/tok/<id>/<sha12>.bin` with
  `Content-Type: application/octet-stream`, `nosniff` and `immutable` (06 §6).
- The loader sniffs the payload (`1F 8B` vs `TSBV`) and verifies `sha256` or `sha256Raw` accordingly (AD-37).
- Specials ship inside the asset in source order (`SPCL`, AD-12); Gemma 4 ships its exact merge table (`MRGS`, AD-6);
  scores are shipped, not derived (AD-7).

## Consequences

- A `.bin` is self-describing (`META` carries provenance), so tests and `tsbs-vocab inspect` need no registry.
- The converter refuses to write an asset that fails its golden fixture (AD-13), with the interim
  `skip-missing-engine` mode until both engines exist (AD-32).
- `.br` siblings can be added in v1.1 through the manifest `encoding` field without a protocol change.

## Reader rules (WP02, `packages/core/src/format/tsbv1.ts`)

The layout leaves some choices to the reader; `readTsbv1` makes them strict so that a writer bug fails loudly at load
time instead of producing wrong tokens (`FormatError { section, offset, reason }`, 04 §5):

- Sections tile the file exactly: 4-byte zero padding after each payload, no trailing bytes, at most one section per
  known tag. Unknown tags are skipped (forward compatibility). Varints are minimal LEB128 of at most 32 bits.
- `META`, `PCES` and `SPCL` are required for both families. `META.family` must match the header byte;
  `META.counts.pieces` / `.specials` / `.merges` must match the decoded sections; `META.maxPieceBytes` must equal the
  longest `PCES` entry (it bounds the engines' merge window); `unicodeVersion` must be `16.0.0` and `unusedCount` 0.
- spm assets must declare `META.priority`: `score` requires exactly one of `PRIO`/`SCRF`, `merge-rank` requires `MRGS`;
  `TYPS` is required and may hold no UNUSED (5) or unknown value. Byte-level assets may carry none of
  `TYPS PRIO SCRF MRGS`.
- `PCES` entries are non-empty and unique. `MRGS` split offsets must fall strictly inside the result piece on a
  code-point boundary (never inside a surrogate pair); a `(result, split)` pair appears once. `SPCL` texts are valid
  UTF-8.
- Every decoded table is an own copy (`ByteVocab` keeps a compact copy of the `PCES` entry bytes, the `MRGS` CSR is
  rebuilt), so the container `ArrayBuffer` is collectable as soon as `readTsbv1` returns.
- `ByteVocab` hashes with 32-bit FNV-1a into 2^ceil(log2(2·count)) `Int32` slots with linear probing; a probe length
  above 64 is rejected (the raw vocabularies measure 19–39). Measured in Node on the development machine: o200k init
  ≈ 7 ms with 4.1 MB resident; Gemma 4 with its 514,906-merge CSR ≈ 30 ms with 8.9 MB.
